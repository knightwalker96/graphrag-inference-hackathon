# Round 3 — Generalizable Context Optimization (SEC filings)

TigerGraph GraphRAG Hackathon, Round 3. Three-pipeline comparison — LLM-only, Basic RAG,
and **TigerGraph GraphRAG** — on 400 SEC filings (100 S&P-100 companies), optimized for
quality-per-token.

## Introduction

**The problem.** In Rounds 1 and 2, every team picked its own dataset and tuned its
pipeline around it — a dataset chosen and known to work well with a graph-based approach
will naturally make GraphRAG look good. Round 3 removes that degree of freedom: TigerGraph
hands **every team the same corpus and the same 50 evaluation questions** — 400 SEC
filings (10-K annual reports, 8-K event filings, DEF 14A proxy statements) for 100 S&P-100
companies — and asks a harder question: *does your context-optimization methodology
actually generalize to data you didn't choose and haven't seen?*

**How this differs from Round 2.** Round 2 was a scale-up exercise: take the approach that
already worked on our own biomedical multi-hop dataset (BioASQ) and prove it holds at
50–100M tokens. The dataset, question style, and knowledge-graph schema were all ones we
designed around from the start. Round 3 is a **generalization test**: a shared, unfamiliar,
heterogeneous corpus (financial filings instead of biomedical text), a shared question set
we had no hand in writing, and — crucially — **40% of the questions are multi-hop
aggregation queries** ("list every company audited by KPMG") that vector search handles
poorly by construction, no matter how well-tuned it is. The scoring also shifted: instead of
rewarding the largest raw token cut, Round 3 rewards the most *rigorously demonstrated*
quality-per-token improvement of GraphRAG over a competent RAG baseline, on data that
wasn't cherry-picked to favor a graph.

**Headline (held-out 50, frozen config v5.2, mean over 3 runs):** GraphRAG **48.7% strict
pass** vs RAG 33.3% vs LLM-only 11.3%, using **50.2% fewer inference tokens** than RAG.
`tg_live=1.0`. The strict-pass lead is ~13× the run-to-run std — statistically real.
See [ARCHITECTURE.md](ARCHITECTURE.md) for the full technical writeup, including the
Pipeline-2 retrieval ablation (adopted config: plain cosine similarity retrieval).

## Reproduce from scratch

```bash
# 1. Questions: parse official eval set + author dev set
python "build/parse_eval_docx.py"
python "build/make_dev_set.py"

# 2. Corpus: 400 filings -> 61k section-aware, citation-ready chunks + Chroma index
python "build/build_round3_corpus.py"
DATASET=round3 EMBEDDING_MODEL=BAAI/bge-small-en-v1.5 ROUND3_PRECHUNKED=1 python build_corpus.py

# 3. Knowledge graph: full-corpus Gemini extraction + targeted precision pass + reconcile
BATCH_CHUNKS=10 EXTRACT_WORKERS=12 python "build/extract_kg.py"
python "build/precision_pass.py"       # auditors 100/100, clean foundry/competitor
python "build/reconcile_edges.py"      # balance precision/recall, real provenance

# 4. TigerGraph: schema (first-class curated edges) + entities + chunk vectors + edges
EMBEDDING_MODEL=BAAI/bge-small-en-v1.5 TIGERGRAPH_GRAPH=finance \
  python "build/round3_tg_ingest.py" --fresh
python "build/smoke_test_tg.py"        # verify agg + vector queries live
```

## Run the benchmark

```bash
# Held-out eval, all 3 pipelines (frozen config)
DATASET=round3 LLM_PROVIDER=gemini GEMINI_MODEL=gemini-2.5-flash \
  EMBEDDING_MODEL=BAAI/bge-small-en-v1.5 TIGERGRAPH_GRAPH=finance P3_REQUIRE_TG=1 \
  MAX_TOKENS=512 CONTEXT_NUM_CHUNKS=10 CONTEXT_CHUNK_CHARS=2000 \
  python "build/run_round3_benchmark.py" --split test --runs 1 --pipelines 1,2,3 --tag heldout

# Evaluate (strict pass + graded + citation + pinned BERTScore)
JUDGE_MODEL=gpt-4o-mini python "build/evaluate_round3.py" \
  results/round3/bench_test_heldout_run1.json --out results/round3/eval_heldout.json

# Ablations (quantify each mechanism)
bash "build/run_ablations.sh"          # GRAPH_OFF, ROUTER_OFF, COMPRESS_OFF

# Dashboard (regenerates a local copy of the hosted dashboard above)
python "build/make_dashboard.py"       # -> dashboard.html, open directly in a browser
```

The 50 held-out questions are stratified by expected GraphRAG benefit: Tier A single-hop
(8 questions), Tier B two-hop bridges (16), Tier C multi-hop aggregation (20), Tier D
cross-document/temporal (6). See [ARCHITECTURE.md](ARCHITECTURE.md) for per-tier results
and known gaps.

## Key design points

- **Same generator, embedder, and context budget** across P2/P3 (fairness). P2 additionally
  uses a cross-encoder reranker P3 lacks — disclosed; it makes P2 the *stronger* baseline.
- **TigerGraph is both the graph and the vector store** for GraphRAG.
- **Fail-loud** (`P3_REQUIRE_TG=1`): GraphRAG aborts if the live graph is unreachable.
- **Actual API token counts** (Gemini `usageMetadata`), not estimates. One-time ingestion
  tokens reported separately (`pipeline3_round3/index/ingestion_tokens.json`).
- **Dev/test isolation**: tuned only on the 24-question dev set; official 50 held out and
  frozen before evaluation.
